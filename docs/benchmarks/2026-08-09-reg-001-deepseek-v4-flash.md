# REG-001 性能基线：TOE-DAC 与直接流程

## 结论

在 Example.com 网页取证与中文报告场景中，TOE-DAC 完整流程耗时 **125.615 秒**；使用同一浏览器工具获取事实和截图，再单次调用相同模型生成报告，完整直接流程约 **6.339–6.671 秒**，中位估算 **6.513 秒**。

本次 TOE-DAC 约慢 **19.3 倍**。它提供了状态机、自动恢复、结构化阶段、双层检查、日志、经验和持久化 Artifact；但对于低风险、单 Action 任务，当前成本明显过高。

### 主要浪费

1. 第一次 Target 自行加入非 canonical 的 `./evidence/`，被确定性规则拒绝；重新生成 Target 额外消耗约 17.269 秒。
2. Observe 总耗时 42.169 秒，其中浏览器只占 4.518 秒，其余主要来自多轮模型工具协议和一次结构修复。
3. Estimate、Decide 和两个 Check 对这个确定性小任务又消耗约 45 秒。
4. 所有阶段串行运行，模型时间几乎等于总墙钟时间。

## 直接流程基线

### 方法

直接流程仍然真实完成用户可见任务：

```text
agent-browser 访问 https://example.com
→ 获取 page_title 和 body_text
→ 保存整页 PNG 截图
→ 单次 deepseek-v4-flash 调用生成简短中文报告
```

它没有执行 TOE-DAC Target、Estimate、Decide、双层 Check、经验记录和状态转换，因此这是“相同用户可见产出”的性能下界，不是等价控制能力的替代实现。

### 实测

浏览器访问、提取和截图耗时 **4.712 秒**。模型使用同一事实输入做 3 次独立生成：

| 样本 | 模型耗时 | Token | 输出字符 |
| --- | ---: | ---: | ---: |
| 1 | 1.959s | 329 | 约 150 |
| 2 | 1.627s | 269 | 127 |
| 3 | 1.801s | 307 | 124 |
| 中位数 | 1.801s | 307 | 127 |

据此：

- 完整直接流程区间：**6.339–6.671 秒**；
- 使用模型中位数的完整流程：**6.513 秒**；
- 若网页事实已经提供、无需真实访问与截图，单次模型生成仅需 **1.627–1.959 秒**，但不满足完整取证任务。

## 后续性能目标

后续优化不通过跳过 TOE-DAC 阶段或取消模型关键判断实现。重点是删除机械 Action、避免模型自造
路径/数值硬约束、复用工具原始证据、减少无意义结构化修复和确认循环，并继续保留六阶段判断、
canonical trace、Artifact、双层 Check、事件日志和异常经验。

## 复测注意事项

- 本报告来自单次 TOE-DAC Session；TOE-DAC 侧还需要至少 3 次独立运行才能形成延迟分布。
- 直接模型侧已经运行 3 次，但浏览器只测量 1 次。
- 网络和模型服务延迟会波动；后续报告必须同时保留每次样本，不只报告平均值。
- Git 工作区不是干净发布快照，因此本报告用于开发基线，不能代表正式 Release 性能。
