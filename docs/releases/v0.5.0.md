# TD Agent v0.5.0 — Storage V2 与可验证迁移

> 本版本把 User Thread 确立为业务持久化入口，Session、日志、证据和 Artifact 均按稳定协议归档。

## Storage V2

- 新 User Thread 写入 `data/user-threads/<user_thread_id>/`。
- `meta.json` 保存非敏感业务与机器元数据；Thread `state.json` 保存调度快照。
- 父子 TD 只在 `td/<td_id>/state.json` 保存自己的状态机上下文。
- Thread 聚合日志统一为 `logs/event.jsonl` 和 `logs/opr.jsonl`。
- 新 Session 使用 `sess-<8位随机码>-<YYYYMMDD_HHMMSS>`，时间按东八区记录，轨迹直接写入 `trace/sessions/<session_id>/`。
- 消息、结构化证据和截图分别使用 `messages.jsonl`、`evidence.jsonl` 和 `screenshots/`。
- `/evidence` 只打开 canonical Session 目录，不生成视图或刷新证据时间。

## 显式迁移

```bash
toe-dac storage migrate
toe-dac storage migrate --execute
```

- 默认只盘点，不写数据。
- 执行时先在临时目录完整构建 V2。
- 校验 TD、Session、消息、事件、操作和证据数量。
- 对所有 Artifact 校验 SHA-256。
- 全部通过后原子切换；旧 `data/threads/` 保留用于回滚。
- 旧 Session ID 保持不变，新建 Session 才采用带时间戳的格式。

## Credentials

- 托管路径固定为 `~/.td-agent/credentials/user-threads/<user_thread_id>/`。
- User Thread 凭据目录权限为 `0700`。
- 拒绝路径穿越、软链接和跨线头读取。

## 兼容性

- v0.4.x 旧结构保持双读。
- Storage V2 是新写入格式，因此版本升级为 `v0.5.0`。
